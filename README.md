# Flow Work OS — рабочий backlog и недельное планирование

Самостоятельное HTML-приложение на русском языке. Внешние библиотеки и сервер для интерфейса не требуются.

## Публикация через GitHub Pages

Репозиторий: https://github.com/gilmiyaroff/marketing_2

1. Откройте **Settings → Pages**.
2. В **Build and deployment** установите **Source: Deploy from a branch**.
3. Выберите **Branch: main**, **Folder: / (root)** и сохраните.
4. После публикации адрес: https://gilmiyaroff.github.io/marketing_2/

**Важно:** GitHub Pages размещает только интерфейс. Задачи сохраняются в localStorage каждого отдельного браузера, не в GitHub. Регулярно сохраняйте экспорт JSON; на другом устройстве копию надо импортировать отдельно.

## Запуск

1. Откройте `index.html` в браузере (предпочтительно Chrome или Safari). Для максимально надёжного хранения данных используйте размещение файла на HTTPS-хостинге.
2. Выберите проект в верхнем левом углу. Предустановлены пустые пространства Qazline, SKVOZNYAK, 6wings. Никакие реальные задачи не импортируются автоматически.
3. Откройте «Недельный план» и задайте доступность в часах (начально `N/A`). Это отдельная настройка для каждого проекта и недели.
4. Введите задачу в «Быстрый захват». Она попадёт в Inbox со статусом «Нужно уточнить», а все неизвестные поля останутся `N/A`.
5. Уточните карточку и переведите её в Backlog, затем задайте приоритет P1/P2, срок (или явно подтвердите отсутствие срока), снимите отметку «Нужно уточнить» и переведите на Board.
6. Укажите оценку часов, после чего добавляйте задачи в недельный план. Приложение блокирует превышение capacity. Для переноса задайте новую неделю и обязательно выберите причину; новая неделя должна иметь установленную capacity.
7. Нажмите «Зафиксировать план», чтобы сохранить исходную версию недели. В «Еженедельном разборе» сравните исходный и текущий планы, факт, блокеры и переносы.
8. Кнопка «Telegram-сводка» формирует компактный текст по текущему проекту и выбранной неделе.

## Экраны

- Обзор, Inbox, Backlog, Сегодня, Эта неделя, Просрочено, На проверке
- Kanban с перетаскиванием задач, календарь сроков
- Недельный план с capacity, факт-часы, фиксация исходного плана
- Еженедельный разбор с ограничениями для новых задач
- По проектам, по ответственным, история изменений и журнал решений

## Где хранятся данные

Данные находятся **только в localStorage этого браузера и сайта/пути запуска**. Это не облачная синхронизация и не многопользовательская база. При очистке данных браузера они могут быть утрачены. Регулярно скачивайте резервную копию через «История и решения» → «Экспорт JSON». Вы можете затем восстановить данные через «Импорт JSON». Перед переносом приложения на новый домен также экспортируйте JSON и импортируйте в новый экземпляр.

## Текущие ограничения

- Нет автоматической интеграции с мессенджерами, CRM, календарями или Sites.
- Нет аккаунтов, командных прав, серверной синхронизации и уведомлений.
- Текстовый быстрый ввод не выдумывает дату, ответственного или объём: эти поля уточняются вручную.
- Факт часов вводится вручную; отсутствие записанных часов не означает, что трудозатрат не было.
- Для реального многопользовательского внедрения рекомендуется авторизация и серверная БД с правами доступа и резервным копированием.
